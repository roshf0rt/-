# Расписание УрФУ для iOS

Стартовый проект для iOS 17+: поиск группы, расписание на ближайшие две недели и виджеты на домашнем экране и экране блокировки. Данные сохраняются в App Group и доступны виджету без сети. Приложение обновляет их при открытии и по жесту обновления списка; виджет переключает занятия по времени и пытается обновить данные в фоне. Частоту фоновых обновлений определяет iOS, поэтому данные могут устареть; при ошибке сохраняется последний кэш.

## Запуск на Mac

1. Установите Xcode и [XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`).
2. В `project.yml` замените `ru.example.UrFUSchedule` и идентификатор расширения на свои уникальные Bundle ID. Замените `group.ru.example.urfu.schedule` на свой App Group ID в `project.yml` и в `Shared/Models.swift`.
3. В папке проекта выполните `xcodegen generate` и откройте `UrFUSchedule.xcodeproj`.
4. В Signing & Capabilities обоих targets выберите свою команду Apple и убедитесь, что одна и та же App Group включена для приложения и расширения. Для тестирования на устройстве возможности подписи зависят от вашей учётной записи Apple.
5. Выберите iPhone или симулятор, запустите приложение и найдите группу. Затем добавьте «Расписание УрФУ» через редактор виджетов домашнего экрана или экрана блокировки.

## Источник данных

Приложение обращается к недокументированным публичным адресам сайта УрФУ `/api/v2/schedule/groups/` и `/api/v2/schedule/groups/{id}/schedule/`. Это не официальный договорённый API: формат и доступ могут измениться, сайт может ответить защитой от ботов. В текущей среде ответы сервера не удалось проверить из-за такой защиты; работу с реальными данными необходимо проверить на устройстве. Кэш сохраняется при ошибке обновления. Часовой пояс занятий — Екатеринбург; время отображается в часовом поясе устройства.

## Сборка в GitHub Actions

При каждом push workflow `iOS build` собирает приложение для iPhone без подписи и загружает `UrFUSchedule-unsigned-ipa` в артефакты запуска на странице Actions. Такой IPA **нельзя установить на обычный iPhone без последующей подписи**; сборка не подтверждает, что сайт УрФУ отвечает на реальные запросы.

Для подписанного Ad Hoc IPA нужны сертификат Apple Distribution с закрытым ключом и два Ad Hoc provisioning profile (для приложения и расширения), созданные в одной команде Apple и с общей App Group. Профили должны содержать устройства, на которые планируется установка. В Settings → Secrets and variables → Actions репозитория задайте variables:

- `APPLE_TEAM_ID` — идентификатор команды Apple;
- `APP_BUNDLE_ID` — Bundle ID приложения; Bundle ID расширения должен быть равен этому значению с суффиксом `.ScheduleWidget`;
- `APP_GROUP_ID` — зарегистрированный идентификатор общей App Group, включённый в оба профиля.

Задайте repository secrets:

- `APPLE_CERTIFICATE_BASE64` — экспортированный `.p12` сертификат с закрытым ключом в base64;
- `APPLE_CERTIFICATE_PASSWORD` — пароль `.p12`;
- `APPLE_APP_PROFILE_BASE64` и `APPLE_WIDGET_PROFILE_BASE64` — содержимое соответствующих `.mobileprovision` файлов в base64.

Не добавляйте эти файлы и значения в репозиторий. В Actions откройте `iOS build` → Run workflow и включите `signed`. Подписанный IPA появится в артефакте `UrFUSchedule-signed-ipa`. Для тестирования на других устройствах или публикации через TestFlight нужны соответствующие профили и способ распространения; этот workflow настроен именно на Ad Hoc.
